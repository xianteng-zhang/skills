## 写作纪律

1. **档位只能用三档**，禁止"综合 78 分"这类无校准依据的精确分。
2. **每条判定后必须跟证据**，没有证据就写「未验证」。
3. **先实测再定性**，实测项和定性项分列，不混写。
4. **偏严**：README 声称但代码里找不到的机制一律按缺失计，并进矛盾清单。
5. **行动项必须标命中第几条判据**，否则用户无法判断优先级。
6. **C 类不放功能**：把已有能力写进简历/README 也是得分手段，这类"零代码改动"的项要显式点出来。
7. **报告写给项目负责人自己**，允许直白；如果报告会被面试官看到，删掉矛盾清单与诚实边界之外的所有对自己不利的内部批注——但**不要删掉行动项里"补事实"的那部分**，那是唯一能真正提高通过率的。
